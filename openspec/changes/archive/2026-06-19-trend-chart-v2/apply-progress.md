### Persistent viewer render disappearance fix
- Root cause: `TrendChartV2Widget.tsx` accepted transient `ResizeObserver` zero-width/zero-height measurements and overwrote the last valid chart size with `0x0`. The viewer could therefore keep the V2 shell, range controls, and zoom helper visible while the SVG plot silently collapsed.
- Fix: preserve only positive measurements, seed dimensions from `getBoundingClientRect()` on mount, and keep the widget shell mounted while surfacing explicit `Loading history...`, `Preparing chart...`, `Sin datos`, or error states.
- Evidence: new strict-TDD regressions cover zero-measurement startup and later transient zero-size resize events without touching legacy `trend-chart`.

### Final visual acceptance corrections — batch 2

### Sparse real-gap regression follow-up
- Root cause: `resolveTrendChartV2GapThresholdMs()` picked the upper-median-ish observed cadence for all sparse series, so a 3-point delta shape like `[1d, 8d]` promoted `8d` into the representative cadence and inflated the split threshold to `12d`, hiding a real sparse gap.
- Fix: keep the existing representative-cadence behavior for larger samples, but treat the 3-point / 2-delta sparse case separately by anchoring the representative cadence to the smaller observed delta before applying the shared multiplier. This preserves the prior tiny-`bucketMs` false-gap fix while restoring real sparse-gap splitting.
- Safety: null splitting, irregular-cadence no-false-split coverage, tiny-backend-bucket protection, and legacy `TrendChartWidget.tsx` isolation all stayed green.

### Screenshot defect follow-up — unresolved 12m left gap + unit label placement
- Root cause: two separate visual issues remained. (1) `TrendChartV2Widget.tsx` intentionally suppressed every singleton segment unless it was the entire series, so a valid first finite 12m point could disappear when a padded/preserved long-range window plus a null/real split left that first point isolated at the left edge; the next multi-point segment then looked like the line started late. (2) the unit label still used a fixed `MARGIN.left / 2` and top margin offset, which ignored the actual Y-scale label anchor and kept the unit too far left/low relative to the top tick.
- Fix: keep the existing 12m padded-window full-width behavior for continuous segments, but also render edge singleton segments as visible V2 points so the first finite rendered point can still sit on plot-left without reconnecting null/real gaps; compute the unit label from chart typography metrics and the Y-scale text anchor so it sits just above the top Y tick label instead of under the header.
- Safety: preserved the prior full-width 12m continuous-path fix, kept null/real gap splitting intact, left zoom/custom-window/backend semantics untouched, and confirmed legacy `TrendChartWidget.tsx` still has zero diff.

### 12m orphan singleton dot bugfix
- Root cause: edge singleton rendering in `TrendChartV2Widget.tsx` still drew `trend-chart-v2-single-point` when an edge segment had one finite point, even if another visible segment already rendered the main connected line. In 12m this produced the observed orphan pink/lilac dot at plot-left while the main line started later.
- Fix: tighten standalone-point rendering so it only appears when the entire visible dataset has exactly one finite point. Connected segments still render line/area normally, and the final point marker remains unchanged.
- Safety: preserved legitimate whole-series single-point rendering with focused coverage, kept the 12m full-width connected-series behavior intact, and left legacy `TrendChartWidget.tsx` untouched.

### 12m left-edge connected-path follow-up
- Root cause: after suppressing the orphan singleton dot, the first connected V2 segment still began at its own first multi-point timestamp instead of the plot-left boundary, so 12m series-extent windows could keep a visible empty gap before the line even though finite data already existed at the left edge.
- Fix: when a 12m series-extent window starts with a suppressed leading singleton and the next visible segment is connected, reuse that left-edge finite point as the anchor for the first rendered connected segment so the line/area starts at plot-left without restoring the orphan dot.
- Safety: limited the anchor behavior to the 12m series-extent edge case, preserved whole-series single-point rendering and final marker behavior, and left legacy `TrendChartWidget.tsx` untouched.

### Persistent 7d dense held-zero split bugfix
- Root cause: `buildTrendChartV2Segments()` treated every >`gapThresholdMs` timestamp jump as a hard break. In 7d dense history the representative cadence stayed 15 minutes, so the standard 1.5x threshold stayed 22.5 minutes and incorrectly split a flat held-value `0 -> 0` interval stretched to only 1.25 hours.
- Fix: keep the existing generic threshold calculation, but add a narrow segment-building bridge for 7d dense cadence only: when the representative cadence is <=30 minutes, adjacent finite points keep the same value, and the stretched interval is <=5 cadence steps, keep the series connected instead of forcing a new segment.
- Safety: materially larger dense-cadence outages still split, coarse 7d/30d bridging remains unchanged, 12m anchor/orphan-dot behavior and final marker rendering stay untouched, and legacy `TrendChartWidget.tsx` still has zero production diff.

### 7d/30d false-gap bugfix
- Root cause: `resolveTrendChartV2GapThresholdMs()` used the global `1.5x` multiplier even for coarse day-scale `7d`/`30d` history, so modestly stretched real intervals (for example ~39h on a daily-ish 7d series or ~3.5d on a 2-day-ish 30d series) were misclassified as true gaps.
- Fix: keep the existing representative-cadence logic, but raise the effective multiplier only for coarse day-scale `7d`/`30d` cadences (`>= 12h`) so continuous flat real history stays connected while true large gaps still split.
- Safety: the renderer already draws line + area from the same `renderablePoints`, so eliminating the false segment split restores the missing stroke alongside the filled segment without touching `12m` anchoring, orphan-singleton suppression, final-point markers, or legacy `trend-chart`.

### 7d/30d false-gap follow-up
- Root cause: the previous coarse day-scale follow-up still capped the `7d`/`30d` bridge budget at `2x` the representative cadence, which remained too strict for the live-like flat ranges reproduced here (`60h` on daily-ish `7d`, `120h` on 2-day-ish `30d`). Segmentation was still the real failure layer: the widget rendered two separate SVG line paths because the utility still returned two segments.
- Fix: keep the segmentation logic in `trendChartV2Segments.ts`, but increase the coarse day-scale multiplier from `2x` to `2.5x` for `7d`/`30d` cadences `>= 12h`. That bridges moderate stretched intervals while preserving visible breaks for materially larger coarse gaps.
- Safety: no renderer branching changed, so `12m` left-edge anchoring, orphan-singleton suppression, final-point markers, null splitting, and legacy `trend-chart` remained untouched; the widget integration regressions prove the SVG now renders one continuous line path for the live-like coarse cases.

### Generalized held-value continuity follow-up
- Root cause: the last tactical fix lived inside `buildTrendChartV2Segments()` as a `7d`-only dense-cadence exception, so the exact same held-value data shape still split in other ranges even though the discontinuity was semantic (`same finite value across a moderate cadence stretch`), not specific to `7d`.
- Fix: replace the range-specific bridge with `resolveHeldValueBridgeBudgetMs()`, a cadence-based helper that allows held-value continuity only when adjacent finite points keep the same value and the stretched interval stays within a named dense/moderate cadence budget; null/invalid points still hard-split, larger same-value outages still split, and changed-value large gaps still split.
- Safety: preserved the existing coarse threshold model, kept 12m orphan-singleton/left-edge-anchor/final-marker behavior green through widget regressions, removed the unused `range` argument from `buildTrendChartV2Segments()`, and left legacy `TrendChartWidget.tsx` untouched.

### Unit label clipping follow-up
- Root cause: `TrendChartV2Widget.tsx` positioned the unit text with a default alphabetic baseline and a width-adjusted centered `x`, so short units like `W`/`KW` could render with glyph pixels above the SVG viewport and get clipped even when the numeric `y` looked positive.
- Fix: anchor the unit label to the Y-axis label column (`x = MARGIN.left - 8`, `text-anchor=end`) and switch the SVG contract to `dominant-baseline="hanging"` at `y=0`, so the text block starts inside the viewport by construction instead of depending on font ascent quirks.
- Safety: preserved the existing 12m no-left-gap/orphan-dot behavior, left `trendChartV2Segments.ts` and legacy `TrendChartWidget.tsx` unchanged, and kept the fix scoped to the V2 unit-label render path plus focused regression tests.

### Unit label separation remediation
- Root cause: the first clipping fix moved the unit label onto the exact same right-edge column as the top Y-axis tick label (`x = MARGIN.left - 8` with both texts `text-anchor=end`), so the unit was viewport-safe vertically but still shared a likely-overlap lane with the top tick.
- Fix: keep the hanging-baseline top-safe contract, but split the columns explicitly: Y tick labels still anchor at `x = MARGIN.left - 8`, while the unit label now anchors one named gap further left (`Y_AXIS_LABEL_X - UNIT_LABEL_COLUMN_GAP`).
- Safety: preserves the V2 plot margin, keeps the unit left of plot start and inside the Y-axis label area, touches no legacy `trend-chart` code, and keeps all prior V2 behavior/tests green.

### Unit label bbox overlap remediation
- Root cause: the second fix only separated the unit and top Y tick by anchor positions while both labels still rendered with `text-anchor=end`, so their actual glyph boxes could still overlap (`KW` extends left from `x=20`, top tick like `3.2` extends left from `x=30`). The bug was about shared rendered intervals, not just distinct anchor coordinates.
- Fix: keep `dominant-baseline="hanging"` at `y=0` for viewport safety, but move the unit to `x = MARGIN.left` with `text-anchor="start"`. That puts the entire unit bbox to the right of plot-left while Y ticks remain entirely left of `x=30`, making the horizontal intervals disjoint by SVG contract without increasing chart margin.
- Safety: keeps the unit visually associated with the Y axis/top of plot, preserves tokenized typography/colors, avoids CSS hacks, touches only `TrendChartV2Widget.tsx`, and leaves legacy `TrendChartWidget.tsx` unchanged.
